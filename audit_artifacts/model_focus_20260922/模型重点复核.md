## 必须优先修复的模型问题

### 1. 能源模型当前实际入口报错；快照验证分支还会改变历史决策

定位：[energy_bubble_radar.py:306](E:/AI/Github_AIProject/html/energy_bubble_radar.py:306)、[energy_bubble_radar.py:309](E:/AI/Github_AIProject/html/energy_bubble_radar.py:309)、[energy_bubble_radar.py:496](E:/AI/Github_AIProject/html/energy_bubble_radar.py:496)。

使用现有 energy_radar_local.csv 调用正式回测函数，得到 `KeyError: "['close'] not in index"`。实际价格列是 XLE，新哈希代码却硬编码 close。

为继续定位，在隔离的合成输入中显式增加 `close=XLE` 别名（仅诊断，不改生产代码）后：

- 无新增数据重复运行报 `Length of values (8) does not match length of index (4)`。`matches` 为空时没有正确设置 start_idx，导致重复重放及数组重复拼接。
- 改变已处理历史价格，哈希失败后仍恢复旧账户和历史数组，再从头执行，报 `Length of values (6) does not match length of index (4)`。恢复语句没有放在验证通过分支内。
- 哈希只检查 date、close、OIL，没有覆盖实际交易条件和其他因子。在价格不变但历史 `Cond_Bubble` 修订的场景中，增量路径成交为 **BUY、SELL**，完整重放只有 **BUY**。这里关注的是多出一笔卖单，不是收益率大小。

修复要求：使用实际 ticker 列；验证成功才恢复，失败必须使用干净状态完整重放；无新增数据直接返回相同业务结果；哈希覆盖全部决策依赖以及策略/特征版本。之后按订单和持仓逐日比较分段与完整回放。

### 2. 订单防重会把重复提交变成漏单

定位：[shared_executor.py:204](E:/AI/Github_AIProject/html/shared_executor.py:204)。

实际顺序是先取消并清空旧 Pending，再检查新 order_id 是否在历史中。对同一天同一买单连续调用两次 submit_order，第二次会将第一次变成 CANCELLED，然后因历史中已有相同 ID 直接返回。

实测次日：**pending=0，fills=0，shares=0，唯一历史订单状态为 CANCELLED**。正常重试不应改变交易意图，却导致买单消失。

修复要求：先判断是否为同一事件的幂等重试，再决定是否替换旧单；若允许同日修改目标，需要显式修订规则，不能将“同日”直接等同于“重复事件”。

### 3. 缺失数据仍改变模型时钟，旧价格仍可能参与新信号

定位：[reflexivity_interactive_chart.py:88](E:/AI/Github_AIProject/html/reflexivity_interactive_chart.py:88)、[daily_market_monitor.py:147](E:/AI/Github_AIProject/html/daily_market_monitor.py:147)。

将本地数据中 **2020-12-01 的 HYG** 单个值置为 NaN，其他输入不变，调用 QQQ 实际模拟函数。原本存在的该日账户记录消失，整个结果一共减少 **470 个账户交易日**。滚动特征缺失向后传播，再被全表 dropna 删除。

这会改变成交时间、定投日期及策略推进，不能视为单纯展示缺值。应保留交易日骨架；特征缺失时通过 signal_ready 阻止依赖该特征的新决策，旧订单及账户估值按独立政策继续处理。

更新脚本也仍将本次没获取的列复制为上一行数值，包括部分行业行情。当前本地主数据末几行中，SPY/QQQ 更新，而 SMH、IGV、XLE、OIL 等重复旧值。这与代码补值路径一致，但仅凭值重复本身不能认定某一日真实市场价格应变化；需要来源时间及质量字段来区分真实平价与陈旧值。不能用新的行日期将旧报价当新成交价。

### 4. NOW 资本因子的来源及历史可用时间尚未核验

定位：[scripts/fetch_now_sec_via_gemini.py](E:/AI/Github_AIProject/html/scripts/fetch_now_sec_via_gemini.py)、[now_reflexivity_radar.py:208](E:/AI/Github_AIProject/html/now_reflexivity_radar.py:208)。

当前 now_sec_fundamentals_local.csv 的 **4,198 行**，三列数值与脚本硬编码季度/半年度节点按 merge_asof 展开后的结果完全一致，最大绝对差均为 **0**。这是数值一致性证据，不等于已经证实这些节点来自官方披露。

本地表只有 date、diluted_shares_m、sbc_pct_rev、insider_net_flow_m，没有来源文件、披露日期、available_at 或口径说明。节点按报告期日期对齐，不能据此证明投资者在那一天已经知道数据。该资本因子在 NOW Composite_Score 中权重为 15%，综合分参与部分顶部/退出条件，故直接影响模型可信度。

另一个 free 生成脚本会线性插值未来节点；本次确认它的输出与当前 CSV **不一致**，因此不把该备选脚本的未来插值直接归因到当前 CSV。当前主要缺陷是可验证来源与历史可用时间缺失。

修复要求：在受控更新阶段保留披露凭证和可用时间，离线模型按 available_at 回看连接。核验前可将该因子标记为实验数据，或在单独版本中禁用，不能继续宣称历史官方数据已验证。

现有 17 项测试：14 通过、2 失败、1 报错。失败原因分别为浮点精确相等、旧同日成交假设；报错为旧指标字段 strat_end。按照本次聚焦模型的要求，这些测试维护问题不作为主要否决依据。上面实际入口报错、漏单、丢交易日和数据来源问题才是重点。

## 最短执行路径

1. 修复能源入口、快照恢复分支以及 submit_order 的防重顺序。
2. 将交易日、特征可用状态、执行价格质量分开，禁止 dropna 删除执行日、禁止旧报价冒充新行情。
3. 核验 NOW 资本因子来源和历史可用时间。
4. 用实际模型入口复验“历史前缀不变、重复运行不改变交易、分段与全量订单一致”。

完成这些才适合继续研究相空间特征是否提供额外信息。后续速度/加速度消融、滚动样本外验证用于证明因子价值，不能用工程测试通过替代；本报告没有声称已完成这些研究。
